# 修复 401 重定向到不存在的 /login

- **日期**：2026-08-13
- **类型**：Bug 修复
- **影响范围**：`app/plugins/request.ts`

## 背景与目标

代码审查（`docs/optimizations/2026-08-13-code-review.md` 高危 7）发现：`app/plugins/request.ts` 的 `onResponseError` 在收到 401 时重定向到 `/login`，但项目登录页真实路由为 `/auth/sign-in`（`app/pages/auth/sign-in/index.vue`），`/login` 不存在——跳转后要么 404，要么被 `auth.global.ts` 再重定向回 `/auth/sign-in`，产生无意义跳转。

上一迭代（GET 鉴权收紧）后 401 更频繁（未登录访问管理 GET 即 401），此 bug 影响被放大，列为下一优先修复项。

## 方案

最小修复：
1. 401 重定向目标改为 `/auth/sign-in`（与 `auth.global.ts` 中间件的跳转目标一致）
2. 401 分支末尾 `return`，避免与下方通用错误 toast（`catchError(error)`）重复弹出两个提示

不引入登录后回跳（`redirect` 参数）：登录页与 `auth.global.ts` 均未消费该参数，属超范围增强。

## 改动内容

- `app/plugins/request.ts`：
  - `navigateTo('/login')` → `navigateTo('/auth/sign-in')`（注释说明真实路由）
  - 401 分支加 `return`，去重 toast

## 验证

- `npx eslint app/plugins/request.ts`：通过，无错误
- `pnpm dev`（运行中）：HMR 输出 `page reload plugins/request.ts` + `Vite server hmr 9 files in 1.123ms`，无编译错误；系统活动（OAuth 登录、会话、菜单查询）正常

## 行为变化

- 会话过期/未登录触发 401 时：跳转到正确的登录页 `/auth/sign-in`（原为不存在的 `/login`），且只弹出一个提示 toast（原为两个）

## 遗留与后续

- 鉴权失败 HTTP 状态仍为 200（body `code=401`，中危 M4），建议后续 `setResponseStatus(event, 401/403)`
- 下一优先项：高危 8（tabStore Map 持久化崩溃）、高危 6（TrafficSource SSR 阻塞 2 秒）
