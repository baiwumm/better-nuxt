# 优化文档

本项目从人工手写转向 AI 主导（Vibe Coding）的持续优化。**每一次优化迭代都必须产出一份独立文档**，沉淀目标、方案、改动与验证结果，形成可追溯的优化史。

## 文档存放

- 路径：`docs/optimizations/`
- 命名：`YYYY-MM-DD-<slug>.md`（如 `2026-07-01-auth-rate-limit.md`）
- 每个优化任务一份文档；同一天多个任务用不同 slug 区分
- 文档只写事实，不写过程流水账；后续可依据文档快速回溯改动

## 文档模板

```md
# <优化标题>

- **日期**：YYYY-MM-DD
- **类型**：新增功能 / 性能优化 / 重构 / Bug 修复 / 依赖升级 / 其他
- **影响范围**：涉及的模块、文件、路由或接口

## 背景与目标

为什么做、要解决什么问题、期望达到什么效果。

## 方案

选用的技术方案与理由；对比过的替代方案（如有）。

## 改动内容

- 改动要点 1（含关键文件路径）
- 改动要点 2
- …

## 验证

- 执行的命令与结果（lint / build / dev 手测 / 迁移等）
- 是否影响既有功能、回归风险说明

## 遗留与后续

未解决的问题、下一步可做的优化。
```

## 执行约束

1. 优化前先明确目标，用 todo 列表拆分步骤，不要一次铺开多个任务
2. 优化以不影响当前功能为前提：默认等价重构，对外行为（API 响应、权限、交互）保持不变；确需改变行为时先说明原因
3. 优化中发现更好的实现方式（技术选型、架构、数据模型、接口契约或影响面更大的替代方案）时，先与用户确认再实施，不擅自采用
4. 遵守根目录 `AGENTS.md` 中的架构与约定（响应格式、权限模型、代码风格等）
5. 安装新依赖前，先检查官方是否提供 skill / MCP（用 `install-capability` 安装），避免重复造轮子
6. 完成一步、验证一步；所有步骤完成后立即补写本文档，不要拖延
